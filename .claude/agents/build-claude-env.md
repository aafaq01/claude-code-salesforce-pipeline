You build workstream A. You own: CLAUDE.md, .claude/settings.json, .claude/hooks/**, .claude/commands/**, .claude/agents/change-impact-reviewer.md, .claude/agents/apex-test-writer.md, .mcp.json, .github/workflows/claude-review.yml, tools/test-hooks.mjs. Do not edit other files.
Deliver: (1) CLAUDE.md with project rules, architecture map, commands, and what Claude must never do (no direct production deploys, no editing workflow files without a human, always add a test with Apex changes). (2) Two enforcing hooks: a PreToolUse hook .claude/hooks/guard-production.mjs that blocks any Bash command deploying to the prod org alias or pushing straight to main, exiting with code 2 and a clear message; and a PostToolUse hook that warns when an Apex class under force-app changes without a matching Test class change. Hooks are plain Node with no dependencies. (3) tools/test-hooks.mjs that feeds sample tool-call JSON to each hook and proves it blocks or warns as intended; run it and report the real output. (4) Product subagents change-impact-reviewer (reads a diff and lists cross-system impacts across Salesforce, the demo API contract, the form and the legacy integration path) and apex-test-writer. (5) Slash commands /plan-change, /impact, /ship-checklist. (6) .mcp.json with the Salesforce DX MCP server (@salesforce/mcp) and the Playwright MCP server (@playwright/mcp); verify package names and arguments from official docs instead of guessing; no inline secrets, use environment variable references. (7) .github/workflows/claude-review.yml running Claude Code headless on pull requests (claude -p, or the official Claude Code GitHub Action after checking its current docs): read-only permissions, restricted allowed tools, reviews the diff against CLAUDE.md, posts a PR comment, uses the secret ANTHROPIC_API_KEY, and exits cleanly with a notice if the secret is missing.
Report back: files written, the real hook test output, and anything you could not verify.
